# تعديلات خريطة دلّيني

هذه طبقتان للطرق ونقاط تهدئة السرعة التي ينشرها مالك التطبيق **للعرض فقط**. ظهور الطريق لا يجعله
جزءًا من حساب المسار، ولا يثبت السماح بالمرور أو اتجاه السير. تبقى بيانات
OpenStreetMap وحزم الملاحة الأصلية مستقلة.

التطبيق المحدّث يقرأ `edits/map.geojson` للطرق و`edits/bumps.geojson` لنقاط
تهدئة السرعة من فرع `main` في مستودع `QasmFD/dallini-offline-data`.
لكل ملف رقم نسخة وتخزين مؤقت مستقلان. ملف الطرق الابتدائي فارغ عمدًا؛ لا يحتوي أي طريق
تجريبي أو مختلق. هذه النسخة في مشروع التطبيق هي تجهيز للنشر، وليست دليلًا
على أنها نُشرت أو فُحصت على الهاتف.

`edits/bumps.geojson` موجود بالفعل في مستودع البيانات. هذا المجلد لا يحتوي
ملفًا ابتدائيًا بديلًا له، حتى لا تستبدل عملية التجهيز النقاط المنشورة.

## رسم طريق وتحديثه

1. افتح [geojson.io](https://geojson.io/) وارسم خط الطريق الصحيح بأداة الخط.
   استخدم نقاط الطريق التي تريد نشرها، ولا ترفع سجل رحلة خاصة أو إحداثيات
   أشخاص. الموقع محرر بيانات جغرافية خارجي.
2. احفظ الناتج بصيغة GeoJSON. احتفظ بعناصر `LineString` فقط. لكل عنصر أضف
   `id` فريدًا مثل `owner:basra-road-01`، واجعل `properties` بالشكل
   `{"kind":"road","name":"اسم الطريق"}`. الاسم اختياري؛ احذف خصائص
   الألوان والأسلوب وأي خصائص أضافها المحرر.
3. انقل العناصر إلى مصفوفة `features` في `edits/map.geojson`. أبقِ الحقول
   الأخرى كما هي، وزد `revision` بواحد عند كل تعديل أو حذف. قد يحذف محرر
   الرسم حقول دلّيني الإضافية؛ أعدها قبل الحفظ في GitHub.
4. افتح تعديلًا في GitHub وانتظر نجاح فحص **Validate owner map edits**، ثم
   ادمجه في `main`. يُفضّل حماية الفرع واشتراط هذا الفحص قبل الدمج؛ ملف
   الفحص وحده لا يفعّل حماية الفرع تلقائيًا.
5. التطبيق المحدّث يفحص التغييرات أثناء ظهوره واتصاله بالإنترنت، بفاصل لا
   يقل عن خمس دقائق. التخزين المؤقت لدى GitHub وحالة الشبكة قد يضيفان
   تأخيرًا؛ ظهور التعديل ليس فوريًا مضمونًا. بعد تنزيل نسخة صحيحة تبقى
   متاحة للعرض دون إنترنت. النسخة غير الصالحة لا تستبدل آخر نسخة صحيحة.

للحذف، احذف عنصر الطريق ثم زد `revision`. لإزالة كل هذه الطبقة، اجعل
`features` فارغة مع زيادة الرقم. وللرجوع إلى رسم سابق، استخدم محتواه مع
رقم جديد أكبر؛ لا تُنقص الرقم ولا تعِد استخدامه لمحتوى مختلف.

## شكل الملف

```json
{
  "type": "FeatureCollection",
  "schema_version": 1,
  "revision": 1,
  "attribution": "Dallini owner map edits",
  "features": []
}
```

كل عنصر يتكوّن فقط من `type: "Feature"` و`id` و`properties` و`geometry`.
الهندسة هي `{"type":"LineString","coordinates":[...]}`؛ كل نقطة داخل
`coordinates` هي `[خط الطول، خط العرض]` كرقمين. لا تنشر صيغة المثال هذه
قبل استبدال النقاط برسمك الصحيح.

الحدود: 1 MiB للملف، 2,000 طريق، 500 نقطة للطريق، و100,000 نقطة إجمالًا.
يجب أن يحتوي الخط نقطتين مختلفتين على الأقل. نطاق الإحداثيات المقبول هو
خط الطول 36.5 إلى 50.5 وخط العرض 27 إلى 39. هذا نطاق تحقق واسع حول العراق،
وليس اختبارًا لوجود طريق أو لحدود الدولة الدقيقة.

المعرّف يبدأ بـ`owner:`، ثم حرف إنكليزي صغير أو رقم، وبعده أحرف صغيرة أو
أرقام أو `_` أو `-`، بطول لا يزيد عن 64 حرفًا بعد النقطتين. لا تكرر
المعرّفات. الاسم لا يزيد عن 120 محرف Unicode، ولا يحتوي مسافات طرفية أو
محارف تحكم/اتجاه خفية أو `<` أو `>`. الوسوم غير المعروفة، المفاتيح المكررة،
النقاط غير الرقمية، والحقول الخاصة أو بيانات صلاحية الملاحة مرفوضة.

هذا التحقق يمنع حقول التتبع الخاصة من دخول الصيغة؛ لا يستطيع أن يستنتج من
الإحداثيات وحدها إن كان شخص قد نسخ رحلة خاصة. راجع مصدر الرسم قبل نشره.

## الفحص المحلي

الأداة تحتاج Python 3.10 أو أحدث ولا تحتاج مكتبات خارجية:

```sh
python tools/validate_map_edits.py edits/map.geojson
python tools/validate_map_edits.py edits/map.geojson --previous previous-map.geojson
python tools/validate_map_edits.py edits/bumps.geojson --feed bumps
python tools/validate_map_edits.py edits/bumps.geojson --feed bumps --previous previous-bumps.geojson
python -m unittest discover -s tools -p 'test_validate_map_edits.py'
```

الخيار `--output new-map.geojson` ينشئ نسخة JSON معيارية جديدة بعد التحقق؛
يرفض استبدال أي ملف موجود. لا تنشر الأداة شيئًا ولا تتصل بالشبكة. تقريرها
يتضمن رقم النسخة والعدد والحجم وبصمة المحتوى فقط.

## نقاط تهدئة السرعة

ملف `edits/bumps.geojson` له `type: "FeatureCollection"` و`schema_version: 1`
و`attribution: "Dallini owner bumps"`. يبدأ `revision` من 1 ويزيد عند أي
تغيير، بما فيه حذف نقطة. لا تربطه برقم نسخة ملف الطرق. لإزالة جميع النقاط
أبقِ الملف مع `features: []` ورقم نسخة أعلى؛ حذف الملف نفسه لا يسحب آخر
نسخة صحيحة مخزنة على الهاتف.

كل عنصر له `type: "Feature"` ومعرّف `owner:` فريد و`geometry` من نوع
`Point` بإحداثيات واحدة `[خط الطول، خط العرض]`. حقول `properties` المطلوبة:

```json
{"kind":"bump","subtype":"hump","source":"osm","source_date":"2026-10-28"}
```

يمكن إضافة `name` فقط كحقل اختياري، مع حدود الاسم نفسها للطرق. القيم المقبولة
لـ`subtype` هي `bump` و`hump` و`table` و`cushion` و`dip` و`rumble_strip`
و`choker` و`chicane` و`yes`. التاريخ يجب أن يكون تاريخًا تقويميًا صحيحًا
بالأرقام الإنكليزية بصيغة `YYYY-MM-DD`، والسنوات من 0001 إلى 9999.
الحدود هي 1 MiB و2,000 نقطة ضمن نطاق الإحداثيات المذكور أعلاه.

أبقِ النوع الوارد في المصدر: `choker` تضييق للطريق و`yes` تهدئة غير محددة؛
ليسا دليلًا على وجود مطب مرتفع. يعرض التطبيق هذين النوعين بتنبيه عام بدل
تمثيلهما كمطب مثبت. هذه الطبقة لا تغيّر حساب المسار ولا تنشئ بلاغًا من السائق
أو تأكيدًا من المستشعرات. `source: "osm"` وتاريخه تصريح من ناشر الملف؛
التحقق الشكلي لا يثبت مصدر OSM أو دقة الموقع أو حالة الطريق الحالية.

الفحص في GitHub يفحص **الملفين** ومقارنة كل منهما بنسخته السابقة. تمرير
ملف الطرق لا يعني أن ملف المطبات مرّ بالفحص. بعد تحديث التطبيق، يجري فحص
كل طبقة أثناء ظهوره واتصاله، بفاصل لا يقل عن خمس دقائق؛ قد تضيف الشبكة
وتخزين GitHub المؤقت تأخيرًا. الخطأ في إحدى الطبقتين لا يمحو آخر نسخة صحيحة
من الطبقة الأخرى.

## تجهيز هذا المجلد في مستودع البيانات

عند التحديث انقل فقط `tools/` وملف العمل داخل `.github/workflows/` وهذه
التعليمات إلى مستودع البيانات العام. أبقِ ملفي `edits/map.geojson` و
`edits/bumps.geojson` المنشورين كما هما؛ لا تستبدلهما بنسخ الاختبار أو الملف
الفارغ الموجود هنا. لا تنقل مشروع التطبيق أو مفاتيحه
أو قواعده الخاصة أو سجلات الرحلات. لا يستبدل هذا التجهيز حزم الخرائط
الإقليمية أو إصداراتها السابقة.

مرجع المحرر: [المشروع الرسمي لـgeojson.io](https://github.com/mapbox/geojson.io).
إعداد الفحص يتبع [أحداث GitHub Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows)
و[إرشادات الأمان الرسمية](https://docs.github.com/en/actions/reference/security/secure-use):
صلاحية قراءة فقط وتثبيت أداة سحب المصدر على بصمة محددة، دون أسرار نشر.

## تحديث النقاط الوطنية من المصدر

ملف `hazards/road-hazards.geojson` مستقل عن تعديلاتك وحزم الملاحة. يحوي
المطبات الرأسية وكاميرات السرعة الثابتة ونقاط التفتيش ومراكز الشرطة المسجّلة
في استخراج العراق الرسمي من Geofabrik/OSM؛ لا يثبت اكتمال المسح الميداني.
التطبيق يفحص هذه الطبقة كل 30 دقيقة أثناء ظهوره واتصاله، ويحفظ آخر نسخة
صالحة مع نسخة مضمّنة للعمل دون إنترنت. لا تتغير حسابات المسار بهذه الطبقة.

العمل `Refresh Iraq source signs` يفحص المصدر يوميًا عند 04:23 UTC
(07:23 بتوقيت بغداد)، وقد يؤخر GitHub التنفيذ. يتحقق من التاريخ والبصمة
والصيغة والإحداثيات قبل نشر الملف وبيان مصدره في تغيير واحد. يحتفظ بالنسخة
السابقة عند فشل الجلب أو الفحص. لا يعدّل ملفي تعديلات المالك أو يعيد بناء
شبكة الطرق والملاحة. التشغيل اليدوي يعيد الاستخراج كاملًا للتحقق من قابلية
إعادة الإنتاج؛ التشغيل الدوري يتجاوز التنزيل عندما لم يتغير المصدر.

هذا العمل وحده يملك صلاحية كتابة محتوى المستودع؛ لا يحتاج مفتاحًا شخصيًا،
ولا يرسل بيانات مستخدمين. يفشل النشر بأمان عند وجود تعديل متزامن بدل فرضه.
قد يعطل GitHub الجدولة في مستودع عام خامل وفق سياسته؛ راجع تبويب Actions
إذا تقادم تاريخ المصدر. يمكن تعطيل العمل، وللتراجع انشر المحتوى الصحيح
برقم `revision` أعلى مع تاريخ مصدر لا يرجع إلى الوراء؛ لا تخفّض رقم الإصدار.
